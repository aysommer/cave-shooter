# Cave Shooter — план разработки

Пиксельный 2D-шутер с видом сверху для двух игроков в браузере: процедурные пещеры, быстрые перестрелки, оружие со своим «характером», мутации между уровнями. Жанр и ощущения как у Nuclear Throne, но персонажи, графика, звуки, оружие и названия свои.

---

## 1. Что нужно

### Технологии
| Что | Выбор | Почему |
|---|---|---|
| Язык | JavaScript (ES-модули), позже по желанию JSDoc/TypeScript | Без компиляции, сразу в браузере |
| Рендер | Canvas 2D, внутреннее разрешение 320×180 (или 384×216) с целочисленным масштабированием | Чёткие пиксели, без размытия |
| Движок | Свой минимальный (~1500–3000 строк) | Полный контроль над «game feel» (тряска, хитстоп, отдача). Phaser можно взять, но он больше мешает, чем помогает в таком жанре |
| Сборка / dev-сервер | Vite | Горячая перезагрузка, сборка в один `dist/` |
| Звук | Web Audio API (+ jsfxr для генерации SFX) | Низкая задержка, много звуков одновременно |
| Ввод | Клавиатура, мышь, Gamepad API | Для двоих на одном ПК нужны геймпады или раскладка «один на клавиатуре, другой на клавиатуре/геймпаде» |
| Графика | Aseprite (~$20) или бесплатно LibreSprite / Piskel | Спрайты 16×16 и анимации |
| Хостинг | GitHub Pages / itch.io / Netlify | Бесплатно |
| Онлайн (опционально) | Node.js + WebSocket (`ws`) или WebRTC (PeerJS) | Только если нужна игра по сети |

### Ключевое решение: что значит «на двоих»
1. **Локальный кооп (рекомендую начать с него)**: два игрока за одним компьютером, общий экран, камера держит обоих в кадре. Просто, без сервера.
2. **Онлайн-кооп**: каждый в своём браузере. Нужен сервер или P2P, синхронизация, борьба с задержкой. Это **в 2–3 раза** больше работы и постоянные расходы на сервер.

План ниже: сначала локальный кооп (этапы 0–9), онлайн отдельно (этап 10). Архитектуру сразу строим так, чтобы онлайн потом можно было добавить: детерминированный фиксированный шаг, ввод отделён от логики, seed для генерации.

## 4. Этапы

У каждого этапа есть **критерий готовности**: что можно запустить и проверить. Этап закрываем коммитом, перед следующим играем сами.

### Этап 0 — Каркас (2–4 ч)
- Vite, `index.html`, canvas 320×180 с целочисленным масштабированием на весь экран, `image-rendering: pixelated`.
- Игровой цикл: **фиксированный шаг 60 Гц** для логики + интерполяция при отрисовке.
- Модули: `input` (клавиатура и мышь), `renderer` (спрайты, прямоугольники, текст пиксельным шрифтом), `assets` (загрузка картинок и звуков), `rng` (seed-генератор, например mulberry32).
- Отладочный оверлей (F1): FPS, число сущностей, хитбоксы.

✅ Готово, когда квадрат двигается по экрану на WASD, пиксели чёткие при любом размере окна.

### Этап 1 — Один игрок, движение и стрельба (5–8 ч)
- Игрок: движение с ускорением и трением, прицел мышью, спрайт поворачивается к курсору.
- Оружие в руке крутится за прицелом. Пули: скорость, время жизни, разброс.
- Тайловая карта (16×16), коллизии AABB со стенами (раздельно по X и Y, чтобы скользить вдоль стен).
- Камера следует за игроком и чуть смещается к курсору.

✅ Можно бегать по тестовой комнате и стрелять, пули гаснут о стены.

### Этап 2 — Процедурная генерация пещер (6–10 ч)
- Алгоритм «бродяги» (random walkers): 1–3 бродяги прокапывают пол от старта, иногда поворачивают, иногда выкапывают комнаты 2×2 / 3×3, пока не наберётся N клеток.
- Автотайлинг стен (битовая маска 4 или 8 соседей), декор.
- Расстановка: старт игрока, враги подальше от старта, сундуки (оружие, патроны), выход.
- Разрушаемые стены (взрывами) — сразу закладываем в структуру карты.
- 2–3 биома: разная палитра, тайлсет и набор врагов.

✅ Каждый запуск (или новый seed) даёт новую связную пещеру, по R — регенерация.

### Этап 3 — Враги и бой (10–15 ч)
- Сущность «враг»: HP, хитбокс, состояния (idle / chase / attack / hurt / dead).
- Простой ИИ: видит игрока (raycast по тайлам), подходит на дистанцию, стреляет с упреждением или без, бродит, если не видит.
- 4–5 типов для начала:
  1. Мелкий бегун (ближний бой).
  2. Стрелок (одиночные выстрелы).
  3. Танк (медленный, много HP, веер пуль).
  4. Подрывник (бежит и взрывается).
  5. Турель / гнездо (стоит на месте, выпускает мелочь).
- Урон, отбрасывание, неуязвимость после попадания, смерть игрока.
- Уровень пройден, когда убиты все враги → открывается портал.

✅ Можно пройти уровень, убив всех, и умереть.

### Этап 4 — «Game feel» (6–10 ч) ← самый важный этап
- Тряска экрана (зависит от оружия и взрывов), хитстоп (замирание на 2–4 кадра при сильном ударе).
- Вспышка спрайта белым при попадании, дульная вспышка, гильзы, отдача (игрок и камера отталкиваются назад).
- Частицы: искры, кровь/слизь, пыль, дым от взрывов.
- Трупы и следы остаются на полу (рисуем в отдельный «канвас пола», это бесплатно по производительности).
- Звуки: выстрел, попадание, смерть врага, подбор, взрыв (jsfxr). Слегка рандомизируем высоту тона.
- Курсор-прицел, анимации ходьбы и простоя.

✅ Стрелять приятно даже в пустую стену. Дайте поиграть кому-то со стороны.

### Этап 5 — Второй игрок, локальный кооп (6–10 ч)
- Схемы управления:
  - P1: клавиатура + мышь, P2: геймпад (основной вариант);
  - оба на геймпадах;
  - запасной вариант на одной клавиатуре: P1 — WASD + стрелять на пробел, прицел автоматический к ближайшему врагу (или 8 направлений); P2 — стрелки + Enter.
- Gamepad API: левый стик — движение, правый — прицел, триггер — огонь, мёртвая зона.
- Общая камера: центр между игроками, отдаляться нельзя (пиксель-арт), поэтому игроков удерживаем в пределах экрана (невидимая «резинка»).
- Отдельные HP и патроны, общий счёт.
- Смерть одного: он становится «призраком», второй может воскресить его, постояв рядом N секунд (или он возрождается на следующем уровне). Game over, когда пали оба.
- Экран подключения: «нажмите кнопку, чтобы присоединиться», игра работает и в одиночку.
- Дружественный огонь отключён (можно сделать опцией).

✅ Двое проходят уровень вместе на одном экране.

### Этап 6 — Оружие и лут (8–12 ч)
- Оружие описываем **данными** в `data/weapons.js`: тип патронов, урон, скорострельность, разброс, число пуль, скорость, отдача, тряска, звук, спрайт, поведение снаряда.
- 5 типов патронов (пули, дробь, энергия, взрывчатка, болты), у каждого свой лимит.
- 15–25 видов оружия: пистолет, автомат, дробовик, двустволка, гранатомёт, лазер, арбалет, оружие ближнего боя (взмах с отражением пуль) и т.д.
- Два слота, смена оружия, подбор с пола, сундуки с оружием и патронами, патроны и аптечки выпадают из врагов.
- Чем глубже уровень, тем лучше оружие в сундуках.

✅ Каждый ран играется по-разному из-за найденного оружия.

### Этап 7 — Прогрессия рана и мутации (6–10 ч)
- Враги дают «опыт» (кристаллы), шкала уровня.
- После уровня экран выбора: 1 из 4 мутаций (пассивные бонусы). В коопе каждый выбирает по очереди или для себя.
- 15–20 мутаций: +HP, больше патронов, быстрее перезарядка, взрыв при смерти врага, вампиризм, точность, магнитный подбор и т.д.
- Структура рана: биом 1 (3 уровня) → босс → биом 2 (3 уровня) → босс → биом 3 → финальный босс. Сложность (число и типы врагов) растёт с глубиной.

✅ Есть полный ран от начала до конца с нарастающей сложностью.

### Этап 8 — Персонажи и боссы (10–15 ч)
- 2–4 играбельных персонажа, у каждого активная способность на ПКМ / кнопку (рывок, щит, гранаты, призыв помощника) и пассивка.
- 2–3 босса с фазами и паттернами атак (веера пуль, призыв мелочи, рывки), полоска HP.
- Экран выбора персонажа для обоих игроков.

✅ Боссы проходимы, но требуют внимания. Персонажи ощущаются по-разному.

### Этап 9 — Меню, UI, полировка, релиз (10–15 ч)
- Главное меню, пауза, настройки (громкость, переназначение клавиш, тряска вкл/выкл, масштаб), экран смерти со статистикой.
- HUD для двоих: HP, патроны, оружие у каждого в своём углу.
- Сохранение в `localStorage`: настройки, рекорды, открытые персонажи.
- Музыка по биомам, плавные переходы.
- Производительность: пул объектов для пуль и частиц, отсечение невидимого, проверка на слабом ноутбуке.
- Баланс-проход: таблица всех чисел в `data/balance.js`.
- Сборка и публикация на itch.io и/или GitHub Pages.

✅ Игру можно скинуть другу по ссылке.

### Этап 10 (опционально) — Онлайн-кооп (50–100 ч)
- Вариант А, **P2P (WebRTC, PeerJS)**: один игрок — хост (симулирует мир), второй присылает ввод и получает состояние. Сервер нужен только для соединения (бесплатный PeerJS cloud или свой). Почти бесплатно.
- Вариант Б, **авторитетный сервер (Node.js + WebSocket)**: честнее и стабильнее, но VPS $5–20/мес.
- Задачи: лобби и коды комнат, сериализация состояния (снапшоты 20–30 Гц + дельты), предсказание движения своего игрока, интерполяция чужих сущностей, переподключение, синхронизация seed генерации уровня.
- Рекомендация: начать с варианта А, логика «хост симулирует, клиент рисует».

✅ Двое играют из разных городов при пинге до 100 мс без заметных рывков.

## 5. Риски и как их снизить
| Риск | Что делаем |
|---|---|
| Игра «не ощущается» | Этап 4 делаем рано, до кучи контента. Тестируем на живых людях |
| Арт тормозит всё | Сначала заглушки / CC0-пак, свой арт потом, по одному набору за раз |
| Разрастание объёма | Всё лишнее идёт в список «потом». Сначала доводим этапы 0–5 |
| Онлайн ломает архитектуру | Сразу: фиксированный шаг, seed-RNG, ввод как отдельная структура, никакого `Math.random()` в логике |
| Производительность при сотнях пуль | Пулы объектов, пространственная сетка для коллизий |
| Сходство с чужой игрой | Свои персонажи, названия, палитра и оружие; заимствуем только жанровые механики |

## 6. Порядок работы
1. Берём этап, разбиваем на задачи прямо в чате.
2. Пишем код, после каждой заметной части запускаем и смотрим.
3. Коммит в конце этапа, плейтест, короткие заметки о том, что поправить.
4. Переходим к следующему этапу.

**Следующий шаг: Этап 0 (каркас).**
