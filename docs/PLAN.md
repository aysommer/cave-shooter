# Cave Shooter — план разработки

Пиксельный 2D-шутер с видом сверху для двух игроков **по сети** в браузере: процедурные пещеры, быстрые перестрелки, оружие со своим «характером», мутации между уровнями. Жанр и ощущения как у Nuclear Throne, но персонажи, графика, звуки, оружие и названия свои.

> ## ⚠️ ОБЯЗАТЕЛЬНОЕ ТРЕБОВАНИЕ: ИГРА ПО СЕТИ
> Два игрока играют **каждый в своём браузере, на своём компьютере**, через интернет.
> Локальный кооп за одним экраном **не является целью** (можно добавить потом как бонус).
>
> Что из этого следует для всего проекта:
> - Сеть закладывается **с самого начала** (этап 2), а не прикручивается в конце.
> - Вся игровая логика детерминирована: фиксированный шаг 60 Гц, свой seed-RNG, **никакого `Math.random()` и `Date.now()` в логике**.
> - Ввод игрока — отдельная структура данных (`{moveX, moveY, aimAngle, fire, alt, swap, ...}`), логика не читает клавиатуру напрямую.
> - Логика мира (симуляция) полностью отделена от отрисовки и звука.
> - Каждый новый этап (враги, оружие, мутации, боссы) **проверяется в сетевой игре двух клиентов**, не только локально.

> ## 🎨 ОБЯЗАТЕЛЬНОЕ ТРЕБОВАНИЕ: НАРИСОВАТЬ 4 ГЛАВНЫХ ГЕРОЕВ НА ВЫБОР
> **Лиса, жаба, гусь, собака.** Имена, способности и требования к спрайтам — в разделе [«Герои»](#герои).
> **Каждый игрок выбирает только 1 героя**, и один и тот же герой не может быть у обоих игроков.

> ## 🐳 ОБЯЗАТЕЛЬНОЕ ТРЕБОВАНИЕ: РАЗВЁРТЫВАНИЕ ЧЕРЕЗ DOCKER
> Вся серверная часть (раздача клиента, signaling, TURN, HTTPS) поднимается **одной командой `docker compose up -d`** на любом VPS или локально.
> Подробности в разделе [«Развёртывание через Docker»](#5-развёртывание-через-docker).

## 1. Что нужно

### Технологии
| Что | Выбор | Почему |
|---|---|---|
| Язык | JavaScript (ES-модули), позже по желанию JSDoc/TypeScript | Без компиляции, сразу в браузере |
| Рендер | Canvas 2D, внутреннее разрешение 320×180 (или 384×216) с целочисленным масштабированием | Чёткие пиксели, без размытия |
| Движок | Свой минимальный (~2000–4000 строк) | Полный контроль над «game feel» и над сетевой синхронизацией |
| Сборка / dev-сервер | Vite | Горячая перезагрузка, сборка в один `dist/` |
| Звук | Web Audio API (+ jsfxr для генерации SFX) | Низкая задержка, много звуков одновременно |
| Ввод | Клавиатура + мышь, Gamepad API | Каждый игрок управляет со своего ПК |
| **Сеть** | **WebRTC DataChannel через PeerJS** (P2P, «хост + клиент») | Задержка ниже, чем через сервер; сервер нужен только для соединения |
| **Signaling** | Свой `peerjs-server` (Node.js) в Docker-контейнере; PeerJS Cloud — запасной вариант | Обмен адресами при подключении |
| **STUN / TURN** | Свой coturn в Docker-контейнере; запасной вариант — Cloudflare Calls / metered.ca (бесплатный тариф) | Без TURN 10–20% игроков за строгими NAT не смогут соединиться |
| Графика | Aseprite (~$20) или бесплатно LibreSprite / Piskel | Спрайты 16×16 и анимации |
| Хостинг клиента | Nginx в Docker на своём VPS (основной); GitHub Pages / itch.io (зеркало) | Нужен HTTPS (WebRTC требует) |
| **Развёртывание** | **Docker + Docker Compose**, Caddy как обратный прокси с автоматическим HTTPS (Let's Encrypt) | Одинаковое окружение локально и на сервере, разворот одной командой |
| CI/CD | GitHub Actions: тесты → сборка образов → публикация в GHCR → `docker compose pull && up -d` на VPS | Обновление сервера без ручных шагов |

### Сетевая модель
- **Хост-авторитет:** игрок, создавший комнату, — хост. Только у него идёт настоящая симуляция мира (враги, пули, урон, лут).
- **Клиент** каждый тик отправляет хосту свой ввод и получает от хоста **снапшоты** мира (20–30 раз в секунду, с дельта-сжатием).
- **Своего персонажа клиент предсказывает** локально (client-side prediction) и мягко поправляет по данным хоста (reconciliation), чтобы управление не «плыло» при пинге.
- **Чужие сущности** (второй игрок, враги) клиент рисует с задержкой ~100 мс, интерполируя между снапшотами.
- **Выстрелы своего игрока** клиент показывает сразу (вспышка, звук, «призрачная» пуля), а результат (урон) решает хост.
- **Уровень** генерирует каждый у себя по общему seed: по сети передаётся только seed и изменения (разрушенные стены, открытые сундуки).
- Каналы: ненадёжный неупорядоченный — для ввода и снапшотов; надёжный — для событий (смена уровня, выбор мутации, чат, подключение).
- Комнаты по короткому коду (например `CAVE-7K3Q`) или по ссылке-приглашению.

Почему P2P, а не свой сервер: для кооп-игры на двоих читерство не критично, а хост-авторитет даёт ту же модель, что и сервер, без расходов. Если позже понадобится выделенный сервер (матчмейкинг, античит), та же логика запустится в Node.js, потому что симуляция не зависит от браузера.

### Герои
Четыре играбельных героя, выбираются в лобби.

**⚠️ Правило выбора: только 1 герой.**
- Каждый игрок выбирает ровно одного героя на весь забег; сменить героя посреди забега нельзя.
- Герой, которого взял один игрок, недоступен второму: в лобби он затемнён и помечен значком напарника. Два одинаковых героя в одной игре невозможны.
- Если оба нажали на одного героя одновременно, его получает тот, чей выбор хост обработал первым; второму показывается «Уже занят».
- Начать игру можно, только когда оба выбрали героя и нажали «Готов».

| | Герой | Характер | Активная способность (ПКМ) | Пассивка | HP / скорость |
|---|---|---|---|---|---|
| 🦊 | **Лиса Шпилька** | Шустрая и наглая, обчистила полпещеры | **Рывок:** короткий бросок с неуязвимостью на время рывка | Быстрее всех бегает, чаще находит патроны | Мало HP / быстрая |
| 🐸 | **Жаба Бульба** | Флегматичная, ничему не удивляется | **Язык:** хватает дальний лут или притягивает лёгкого врага к себе | Ядовитая кожа: враги вплотную получают урон; иммунитет к кислотным лужам | Средне / средняя |
| 🪿 | **Гусь Генерал Га** | Злой, громкий, никого не боится | **Гогот:** конус перед собой отбрасывает врагов и сбивает вражеские пули | Больше HP, сильный щипок в ближнем бою | Много HP / медленный |
| 🐶 | **Пёс Бублик** | Добряк, лучший напарник в коопе | **Апорт:** собирает весь лут и патроны в радиусе вокруг | Поднимает упавшего напарника вдвое быстрее, чует сундуки (стрелка к ближайшему) | Средне / средняя |

**Что нарисовать для каждого героя:**
- Спрайт 16×16: стойка (4 кадра), бег (6 кадров), получение урона, смерть, «призрак» упавшего игрока.
- Анимация способности (2–4 кадра) и её эффект: шлейф рывка, язык, волна гогота, круг апорта.
- Портрет 32×32 для экрана выбора и HUD напарника.
- Узнаваемый силуэт и цвет на тёмном фоне пещеры: лиса — рыжая, жаба — зелёная, гусь — белый с оранжевым клювом, пёс — коричнево-бежевый.

**Когда:** с этапа 1 вместо жёлтого квадрата используется черновой спрайт лисы Шпильки, на этапе 2 (когда появляется второй игрок) у напарника временно перекрашенная лиса, пока не готовы остальные герои. Все четыре героя с финальными спрайтами и способностями — этап 9.

```
│  │  ├─ level/          # генерация по seed, тайлы, коллизии

│  │  ├─ peer.js         # подключение PeerJS, комнаты, коды
│  │  ├─ protocol.js     # форматы сообщений, бинарная сериализация
│  │  ├─ host.js         # приём ввода, рассылка снапшотов
│  │  ├─ client.js       # отправка ввода, предсказание, интерполяция
│  │  └─ snapshot.js     # снапшоты, дельты, буфер
│  ├─ view/              # отрисовка состояния мира, частицы, тряска, звуки по событиям
│  ├─ ui/                # HUD, меню, лобби, экран мутаций
│  └─ data/              # balance.js, enemies.js, weapons.js, mutations.js
├─ server/               # (позже) dedicated server на Node.js
├─ assets/
├─ deploy/               # конфиги для Docker
│  ├─ Caddyfile          # HTTPS и проксирование
│  ├─ nginx.conf         # раздача собранного клиента
│  ├─ turnserver.conf    # coturn
│  └─ .env.example       # домен, внешний IP, секрет TURN
├─ Dockerfile            # multi-stage: node (vite build) → nginx:alpine
├─ docker-compose.yml    # web, signal, turn, caddy
├─ docker-compose.dev.yml  # локальный запуск: vite + signal + turn без HTTPS
├─ .dockerignore
└─ docs/PLAN.md
```

Главное правило: **`sim/` ничего не знает про экран, звук и сеть.** Она получает состояние и вводы, возвращает новое состояние и список событий («выстрел», «попадание», «смерть»), а `view/` по этим событиям рисует эффекты и играет звуки.

## 4. Этапы

У каждого этапа есть **критерий готовности**. С этапа 2 он всегда проверяется **в двух вкладках/на двух компьютерах по сети**.

### Этап 0 — Каркас (3–5 ч) ✔️ готово
- Vite, `index.html`, canvas 320×180 с целочисленным масштабированием, `image-rendering: pixelated`.
- Игровой цикл: **фиксированный шаг 60 Гц** для логики + интерполяция при отрисовке.
- `input` собирает ввод в структуру `InputFrame` (а не даёт логике читать клавиши).
- `rng`: seed-генератор (mulberry32 / sfc32), состояние RNG — часть состояния мира.
- Разделение `sim/` и `view/` с первого дня.
- Отладочный оверлей (F1): FPS, тик, число сущностей, хитбоксы.

✅ Квадрат двигается на WASD, пиксели чёткие; симуляция работает только через `step(state, inputs)`.

### Этап 1 — Один игрок: движение и стрельба (5–8 ч)
- Игрок: движение с ускорением и трением, прицел мышью (угол передаётся во вводе).
- Оружие в руке поворачивается за прицелом, пули: скорость, время жизни, разброс (через seed-RNG).
- Тайловая карта 16×16, коллизии AABB со стенами (раздельно по X и Y).
- Камера следует за игроком и смещается к курсору.
- Черновой спрайт лисы Шпильки (стойка и бег) вместо квадрата.

✅ Бегаем по тестовой комнате и стреляем, пули гаснут о стены.

### Этап 2 — 🌐 Сеть: двое по интернету (22–38 ч) ← ключевой этап
- **Лобби:** «Создать игру» (получаем код комнаты и ссылку) / «Присоединиться» (ввести код). Статус подключения и пинг.
- PeerJS: подключение, STUN + TURN, обработка обрыва, таймауты.
- **Протокол:** бинарная сериализация (`DataView`/`ArrayBuffer`) вместо JSON, номера тиков, подтверждения (ack).
- **Хост:** принимает ввод клиента, симулирует мир, шлёт снапшоты 20–30 Гц (позже с дельтами).
- **Клиент:** шлёт ввод каждый тик (с повтором последних 3–5 кадров на случай потерь), **предсказывает своё движение** и сверяет с хостом, **интерполирует** второго игрока и пули.
- Выстрелы: клиент сразу показывает свою пулю, хост подтверждает.
- **Отладка сети:** искусственная задержка, джиттер и потеря пакетов (слайдеры в F1-оверлее), графики пинга и размера снапшотов.
- Переподключение клиента в течение 30 с без потери забега.
- **Docker (dev):** `docker-compose.dev.yml` поднимает локально свой signaling (`peerjs-server`) и coturn, клиент подключается к ним через переменные `VITE_SIGNAL_URL` / `VITE_TURN_*`. Так сеть с первого дня тестируется на своей инфраструктуре, а не на чужом облаке.
- Фоновая вкладка: `requestAnimationFrame` в ней останавливается, поэтому симуляцию хоста гоняем по таймеру (или в Web Worker), а не по кадрам отрисовки. Иначе тест «в двух вкладках» и свёрнутый хост сломаются.

✅ Двое на разных компьютерах бегают и стреляют в одной комнате. При эмуляции 150 мс пинга и 5% потерь своё движение отзывчивое, чужое плавное.

### Этап 3 — Процедурная генерация пещер (6–10 ч)
- Алгоритм «бродяги»: 1–3 бродяги прокапывают пол, поворачивают, выкапывают комнаты 2×2 / 3×3.
- Автотайлинг стен (битовая маска), декор.
- Расстановка: старты обоих игроков рядом, враги подальше, сундуки, выход.
- **Сеть:** хост выбирает seed и рассылает его; каждый генерирует сам. Проверка: хеш карты у хоста и клиента совпадает. Разрушенные стены передаются событиями.
- 2–3 биома: своя палитра, тайлсет и набор врагов.

✅ У обоих игроков одна и та же новая пещера, переход на следующий уровень синхронный.

### Этап 4 — Враги и бой (12–18 ч)
- Враг: HP, хитбокс, состояния (idle / chase / attack / hurt / dead).
- ИИ: видит игрока (raycast по тайлам), выбирает **ближайшего из двух игроков** или того, кто нанёс урон, подходит на дистанцию, стреляет, бродит.
- 4–5 типов: бегун, стрелок, танк (веер пуль), подрывник, гнездо/турель.
- Урон, отбрасывание, неуязвимость после попадания, смерть игрока.
- Уровень пройден, когда убиты все враги, тогда открывается портал.
- **Сеть:** враги и вражеские пули только в снапшотах хоста; на клиенте интерполяция. Сжатие: передаём только видимые/изменившиеся сущности. Лимит размера снапшота ~1 КБ.

✅ Двое по сети проходят уровень и могут умереть; у клиента нет «телепортирующихся» врагов при нормальном пинге.

### Этап 5 — «Game feel» (6–10 ч)
- Тряска экрана, хитстоп (2–4 кадра), белая вспышка при попадании, дульная вспышка, гильзы, отдача.
- Частицы, трупы и следы на полу (отдельный канвас пола).
- Звуки (jsfxr) со случайной высотой тона.
- **Сеть:** всё это чисто визуальное, генерируется локально по событиям из снапшотов, по сети не передаётся. Хитстоп не останавливает симуляцию, только отрисовку.

✅ Стрелять приятно, в том числе на стороне клиента с пингом.

### Этап 6 — Кооп-механики (5–8 ч)
- Отдельные HP и патроны, общий счёт и опыт.
- Упавший игрок становится «призраком»; напарник поднимает его, постояв рядом N секунд. Game over, когда пали оба.
- Указатель направления на напарника за краем экрана (у каждого своя камера).
- Пинг-метка («сюда!») по кнопке, простой текстовый чат / эмоции.
- Дружественный огонь выключен (опция в лобби).
- Выход из игры одного игрока: хост продолжает один; если вышел хост — клиент видит экран «хост отключился» (миграцию хоста не делаем).

✅ Полноценная совместная игра по сети с поднятием напарника.

### Этап 7 — Оружие и лут (8–12 ч)
- Оружие описано **данными** в `data/weapons.js`: патроны, урон, скорострельность, разброс, число пуль, скорость, отдача, тряска, звук, спрайт, поведение снаряда.
- 5 типов патронов, 15–25 видов оружия, включая ближний бой с отражением пуль.
- Два слота, смена, подбор, сундуки, дроп из врагов, качество зависит от глубины.
- **Сеть:** передаём id оружия, а не его параметры; подбор решает хост (кто первый взял).

✅ Каждый забег по-разному играется из-за найденного оружия.

### Этап 8 — Прогрессия забега и мутации (6–10 ч)
- Опыт (кристаллы), шкала уровня.
- Между уровнями каждый игрок выбирает 1 из 4 мутаций **у себя**; переход дальше, когда оба выбрали (с таймером).
- 15–20 мутаций.
- Структура: биом 1 (3 уровня) → босс → биом 2 → босс → биом 3 → финальный босс.
- **Сеть:** экран выбора через надёжный канал, синхронизация готовности.

✅ Полный забег от начала до конца по сети.

### Этап 9 — Герои и боссы (14–22 ч)
- **4 героя: лиса Шпилька, жаба Бульба, гусь Генерал Га, пёс Бублик** (см. раздел «Герои»): финальные спрайты, анимации, портреты, активные способности и пассивки.
- Экран выбора героя в лобби: **каждый выбирает только 1 героя, занятый напарником герой недоступен**. Выбор синхронизирует хост через надёжный канал.
- Баланс: у каждого героя свой стиль игры, ни один не сильнее остальных в коопе.
- 2–3 босса с фазами и паттернами; сложность босса учитывает число игроков.
- **Сеть:** способности с предсказанием на клиенте (рывок должен ощущаться мгновенно).

✅ Боссы проходимы вдвоём; Шпилька, Бульба, Генерал Га и Бублик играются по-разному и узнаются с первого взгляда.

### Этап 10 — Меню, полировка, релиз в Docker (16–26 ч)
- Главное меню, лобби с выбором персонажа и готовностью, пауза (в сети — меню без остановки мира), настройки, экран смерти со статистикой.
- HUD: свои HP/патроны/оружие + мини-панель напарника с пингом.
- `localStorage`: настройки, рекорды, имя игрока.
- Музыка по биомам.
- Производительность: пулы объектов, пространственная сетка для коллизий.
- **Сеть:** тест на реальных соединениях (Wi-Fi, мобильный интернет, разные провайдеры), проверка TURN, свой signaling-сервер, если PeerJS Cloud нестабилен.
- **Разворот через Docker на VPS** (см. раздел 5): `docker compose up -d`, проверка HTTPS, signaling и TURN с внешних сетей.
- **CI/CD:** GitHub Actions собирает образы, публикует в GHCR и обновляет сервер.
- Зеркало клиента на itch.io (с тем же signaling/TURN).

✅ Игру можно скинуть другу по ссылке, он заходит по коду комнаты и играет.

### Этап 11 (опционально, потом)
- Выделенный сервер на Node.js (та же `sim/`) — для честности и игры без хоста.
- Матчмейкинг / публичные комнаты.
- Локальный кооп за одним экраном как дополнительный режим.
- До 4 игроков.

## 5. Развёртывание через Docker

### Сервисы (`docker-compose.yml`)
| Сервис | Образ | Что делает | Порты |
|---|---|---|---|
| `web` | свой, multi-stage: `node:22-alpine` собирает `vite build` → `nginx:alpine` раздаёт `dist/` | Клиент игры (статические файлы) | внутренний 80 |
| `signal` | свой, на основе `peer` (PeerJS server) на `node:22-alpine` | Соединение игроков (WebSocket) | внутренний 9000 |
| `turn` | `coturn/coturn` | STUN/TURN-ретранслятор для игроков за строгим NAT | 3478 UDP/TCP, 5349 TLS, диапазон реле UDP (например 49160–49200) |
| `caddy` | `caddy:2-alpine` | HTTPS с автоматическими сертификатами, `/` → `web`, `/peerjs` → `signal` | 80, 443 |
| `game-server` (этап 11) | свой, `node:22-alpine` + `src/sim/` | Выделенный сервер вместо хоста-игрока | внутренний |

### Как это работает
- Конфигурация через `.env` (по образцу `deploy/.env.example`): `DOMAIN`, `PUBLIC_IP`, `TURN_SECRET`.
- TURN использует временные логины (`use-auth-secret`): signaling выдаёт клиенту логин/пароль на сутки, постоянный пароль в клиенте не хранится.
- `turn` работает с `network_mode: host` (Docker плохо пробрасывает большие UDP-диапазоны), поэтому диапазон реле ограничен и открыт в файрволе.
- У всех сервисов `restart: unless-stopped` и healthcheck; логи с ротацией.
- Образы собираются в GitHub Actions и публикуются в GitHub Container Registry; на сервере только `docker compose pull && docker compose up -d`.

### Команды
Локальная разработка:
```bash
docker compose -f docker-compose.dev.yml up
```
Продакшен на VPS:
```bash
docker compose up -d
```

### Когда что появляется
| Этап | Что делаем с Docker |
|---|---|
| 2 | `docker-compose.dev.yml`: signaling + coturn локально |
| 3–9 | Обновляем образы по мере появления сетевых функций |
| 10 | `Dockerfile` для клиента, полный `docker-compose.yml` с Caddy, `.env`, CI/CD, разворот на VPS |
| 11 | Контейнер `game-server` |

✅ На чистом VPS с установленным Docker игра становится доступна по `https://<домен>` после `git clone`, заполнения `.env` и `docker compose up -d`.

## 6. Риски и как их снизить
| Риск | Что делаем |
|---|---|
| **Рассинхрон хоста и клиента** | Хост — единственный источник правды; клиент только предсказывает себя. Хеши карты и состояния в отладочном режиме |
| **Лаги и дёрганье при плохом пинге** | Предсказание + интерполяция + эмулятор задержки/потерь с этапа 2; тестируем при 150 мс и 5% потерь |
| **Не удаётся соединиться (NAT)** | Обязательно TURN; понятная ошибка в лобби |
| **TURN в Docker не пропускает трафик** | `network_mode: host`, ограниченный диапазон портов, открытый в файрволе, правильный `external-ip`; проверка через trickle-ice тест |
| **Сервер упал или переехал** | Всё описано в `docker-compose.yml` и `.env`, разворот на новом VPS за минуты; PeerJS Cloud и публичный TURN как запасной вариант |
| **Сеть ломает уже готовые механики** | Сеть делаем на этапе 2, а каждую новую механику сразу проверяем в двух клиентах |
| **Большие снапшоты** | Бинарный формат, квантование координат, дельты, только видимые сущности |
| Игра «не ощущается» | Этап 5 рано, плейтест с живыми людьми |
| Арт тормозит всё | Сначала заглушки / CC0, свой арт потом |
| Разрастание объёма | Всё лишнее — в этап 11 |
| Сходство с чужой игрой | Свои персонажи, названия, палитра и оружие; из жанра берём только механики |
